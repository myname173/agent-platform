五、顺带挖出的两个「部署静默失败」根因

① n8n 公共 API key 已过期 —— 平台静默降级 12 天

  • 过期时间 2026-10-03 12:00 UTC。症状远不止部署失败：网关查管理密钥返 500、聊天留存报错、冒烟 8 项挂。
  • 机制：user_api_keys.apiKey 存的是原始 JWT，exp 一到即 401。
  • 已签发不过期的新 key，并补上必须显式写入的 scopes（否则 403）。
  • 坑：N8N_API_KEY 是环境变量，改完必须重建容器；且要改两份（根 .env 给 n8n，frontent/.env.local 给控制台）。

② 主题提交 a7a5ae7 把 24 个工作流的 id 换成了别的实例的

  • 部署脚本逻辑是「文件里的 id 查得到就更新，查不到就新建」→ 于是每次部署都翻倍（24→48），激活全部 409 冲突。
  • 识别信号：部署输出里出现 created 而不是 updated。
  • 已按名称把 24 个 id 指回线上真实行，并删掉重复的 24 个。
  • 结论：工作流文件的 id 不是可以随手改的字段。
