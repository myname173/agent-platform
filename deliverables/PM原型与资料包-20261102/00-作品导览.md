## 三分钟讲法（背结构，不背词）

一句话定位：**一个人自托管跑起来的 AI Agent 中台——24 条 n8n 工作流当编排核心，四个入口（对话前台 / 运营控制台 / Telegram / MCP）共用一套业务逻辑，我给它的"可观测 + 可追责"部分做了 PM 定义。**

然后按这个顺序讲，每段一个具体证据：

1. **入口不互调**，全都只打到 n8n。所以改一处，四个入口同时生效——这是产品架构决定，不是技术偏好。
2. **看得见的必须会报警**。成本一直在算，但 TS 类型里没声明 `cost` 字段，控制台没有任何地方读得到——"数据有了、通道没有"等于没有。补了卡片 + `cost_budget` 规则，并且**告警复用统计的同一份数**，不自己重算。
3. **绿灯必须能被证伪**。smoke 71/71 我报数会带 SKIP 状态；自检**分开统计手动与定时**，否则手动跑一次就把"定时任务 3.6 天没跑"这件事盖住。
4. **AI 只有点火权**。自建流程注册成对话工具，模型能触发、不能建/改/删；外部 MCP 服务器要人登记；沙箱审批按 `sha256(代码原文)` 一次性绑定。
5. **我知道哪里还是坏的**：提醒接口在 n8n 2.37.7 下写成功却回 500（留孤儿提醒）、自检的 weekly dry-run 会绕过周守卫把周报吞掉、BUDGET_NOTE 的收口效果**未证实**。

## 边界声明（先说，别让人问出来）

这套作品里，**底座不是我做的**，我说的时候也不会说成自己做的：

- n8n / LobeChat（PivotAI 皮）/ Kiranism 模板 / DeepSeek / DashScope / SearXNG / ParadeDB(Postgres) / MinIO / Caddy / Telegram Bot API —— 这些是我接入与配置的第三方与开源件。
- 控制台的**壳**（侧边栏、主题系统、data-table、Clerk 集成）来自 Kiranism 模板；我做的是 13 个业务页、它们代理的 27 条 api route、`api-guard` 的登录与上游错误语义、以及暗色指挥台那一整块。
- 真实使用规模：**单机自托管，一个机主**。"派发/人员目录/团队周报视图"是按多人协作**设计并实现**的，但我不把它说成"已有多人日常使用"。这条如果对方问起，我直接答这个。
