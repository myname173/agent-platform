# 02 · 信息架构、页面规格与原型说明

原型文件：`原型-三端可交互.html`（单文件，浏览器直接打开，不接真实接口）
画板：`figma/01…08.svg`（分层，可导入 Figma）

## 1. 三端 IA

```
                         ┌──────────────────────────────────────────┐
  入口（互不调用）        │  n8n :5678  ——  唯一的业务逻辑与编排层      │
  LobeChat 前台 :3210 ──▶│  24 条工作流 · 39 条 webhook 唯一路径       │
  运营控制台 :3000     ──▶│  服务端工具 16 静态 + 动态 wf_* · ≤2 轮       │
  Telegram 轮询桥     ──▶└───────────┬──────────────────────────────┘
  外部 MCP 客户端     ──▶            │
                          ┌──────────┴───────────┐
                          ▼            ▼          ▼
                 Postgres17+pgvector  MinIO   stream-bridge :3211
                 （23 张 Data Table，2026-10-30 现网列举 + RAG/ops/platform 三套 schema）
```

- **控制台的登录**是 Clerk；`N8N_API_KEY` / `CHAT_API_KEY` 只存在于 Next.js 服务端（27 条 api route 全部先 `requireUser()`）。
- **前台不直连模型**，经 stream-bridge 侧车；含工具调用时自动降级到网关跑完整循环再回灌打字机。
- **Telegram 桥不是通知器**，它是写回入口：按钮回调直接写 `todos` / `reminders` 同一行。

`frontent/src/config/nav-config.ts:36-160` 是这张表的来源：**五组 14 项导航 = 13 个业务页 + Clerk Profile**（`NAV-01` 断言实测 14 个 title），两键快捷键（如 `o o`、`k b`）也都是真实配置。

两条贯穿全站的约定，是从代码里读出来、不是设计偏好：

- **不用 toast**，用页内彩色 flash 横幅；确认交互是**按钮二次点击变红**（`删除 → 确认删除?`）。
- **错误消息必须可操作**：登录失效与"控制台↔n8n 断了"必须是两句话（`api-guard.ts:17-40`，全文只有 40 行）。

## 3. 前台与 Telegram 的 IA（另两端）

LobeChat 前台（PivotAI v2 皮）：会话列表 → 消息流（深度思考折叠 / 工具轨迹 / 引用记忆与知识库）→ 输入区（流式 / 深度思考 / 知识库 / 记忆 / 语音 / 图片六个开关）→ 模型选择。
两处已知现象在原型里明确标注、不藏：切服务端库后本地 v1 会话不在（列表初始为空）；左上 LobeHub、右上 PivotAI 的品牌不一致。

Telegram 端三类消息 + 一组命令：

| 类别 | 消息 | 可点 | 写回 |
| --- | --- | --- | --- |
| 推送 | 晨报（含 `## 待办速览` 尾段）· 周报 · 动态监控 · 告警 `[PivotAI 告警] kind · message` | 无 | 只读；>3500 字截断并指向控制台 Briefs |
| 提醒 | `⏰ 提醒 · 标题` | `知道了` / `1 小时后再提醒` | `reminders.status=canceled` / `due_at+=1h` |
| 派发 | `📌 新任务` / `⏰ 待办催办` / `🚨 逾期升级` | `我收到了` / `已完成` / `推迟 1 天` | `ack_at`（停催不关单）/ `todos/complete` / `due_date+=24h` |
| 命令 | `/todos /reminders /memory /tools /todo @人 /ack /done /waiting /people /help /reset` | — | 免模型直查，不消耗工具轮 |

## 5. 原型的边界（必须写清，不然被追问会翻车）

- 原型**不连真实接口**：所有按钮走本地状态机，flash 文案是真实实现里的文案，但不会真的写库。
- 数据分三层标注：实机快照（2026-10-30）／结构真实但数值为示意（按窗口、按 key 的拆分）／模板自带 demo（Notifications）。原型底部有图例，打开「需求追溯」可看到每个模块的上游端点。
- 13 页全部存在对应页面文件（我逐个核过）；`Profile` 只渲染 Clerk 组件，所以我没给它编内容。
- `features/knowledge/components/kb-search-card.tsx` 是无引用死代码 —— 检索演练用的是另一条实现，做 IA 时不该把它当页面。
