## 2. 高频追问与我的答法

**Q：这套东西别人也做得到，你的判断体现在哪？**
A：不在"搭起来"，在三处判断：① 成本"看得见"必须与"会报警"同源，否则出现卡片 $1.9 / 告警 $2 的错位；② 绿灯要能被证伪，所以自检把"探首页"升级成"真发一次搜索"、把手动与定时分开统计；③ 模型的权限边界是"点火权"，能力再强也不给建改删。这三条都是**代价明确**的取舍，不是流行做法。

**Q：你说 71/71，那我关掉服务再跑一次会看到什么？**
A：现在会看到 EXIT=1 且**一行计数都不打** —— 因为第一条 `healthz` 的 fetch 没包错误处理，unhandled rejection 直接终止。这是我列的 R-01：门在系统死的时候必须报 `0/71` 加原因。我先把这个缺陷交出来，因为"绿灯时系统已死"是我最不能接受的一类假象。

**Q：为什么不用 Dify / Coze / LangGraph？**
A：我**没有做对照实验**，所以不说"性能更好"。我的两条真实理由：入口不互调这件事 n8n 原生表达（webhook 即端点）；流程可视化能让我在评审时把逻辑直接摊开。代价我也说：单点、工作流 JSON 会与现网漂移（RSK-03）。

**Q：23 张表怎么来的？为什么不直接建 PG 表？**
A：其中大部分是 n8n Data Table（真实结构是 `data_table` + `data_table_column` + `data_table_user_<id>`，**没有同名 PG 表**）。选它是因为工作流节点要能免运维读写；RAG / 告警 / 平台状态机这三套是正经 PG schema。代价是 rows API 的一堆坑（最旧 N 行、limit 250、sortBy 要编码）。

**Q：单人项目，怎么证明不是玩具？**
A：我不说它是产品，我说它有**门禁与台账**：五道门里两条红的我照样复跑；`selfcheck_runs` 138 行、`cron_runs` 100 行、`heartbeats` 35 行、`daily_briefs` 31 行、`idempotency_records` 32 行。规模就是一个人 + 一台机器，我按这个规模做取舍（比如多时间点补跑，而不是上云）。

**Q：安全上你怎么兜的？**
A：三层。① 密钥面：`N8N_API_KEY`/`CHAT_API_KEY` 只在服务端；托管 key 哈希存储、可独立吊销、原始值只出现一次；② 执行面：沙箱默认禁网 + `rlimits` + 容器边界，审批按 `sha256(代码原文)` 一次性绑定；静态扫描只是减速带；③ 不可信输入：外部 MCP 工具列表当不可信数据处理，模型主动拒绝据其执行额外动作 —— **这个姿态我保留不"修"**。
诚实补充：安全评估题集现在 **5/12**，因为沙箱通道还没打通；历史里两个凭证我按已泄露处理，轮换没完成就是没完成（RSK-13）。

**Q：最有代表性的一个 bug？**
A：工具定义四份副本、其中两份是错的、四道门全绿。后果有两层：第 2 轮循环里三个工具消失；带 client_tools 的客户端把它们误判成客户端工具，网关不执行、透传响应 ⇒ **用户收到一条空消息**，而所有门都是绿的。修法是消除副本（第 2 轮复用第 1 轮下发的数组、`SERVER_NAMES` 从同一数组推导），并补两道门：契约三项守卫 + 专门覆盖那条没人走的路径。我的收获是：**新增一条代码路径就要配一道能失败的检查**。

**Q：如果给你团队和三个月？**
A：先做 v1.5 的六条（R-01…R-06），因为它们决定"我说的话能不能被信"。之后才做异步摄取与多人闭环 —— 在没有真实多人使用前，我不做团队视图的推广。

## 4. 数据字典速查（23 张 Data Table + 三套 PG schema）

`admin_audit`(治理留痕) · `chat_executions`(执行/成本/错误原文，90d) · `chat_messages`(消息，30d) · `cron_runs`(多时间点守卫的每日/每周标记) · `daily_briefs` · `documents` · `gateway_keys`(哈希 + rpm + total_cost) · `heartbeats`(备份 stamp/文件数/字节) · `idempotency_records`(7d) · `kb_usage`(累计 embed tokens) · `mcp_servers`(人登记，模型只可用) · `ops_alert_silence`(维护窗口) · `ops_alerts`(kind/severity/delivered) · `people`(通道/时区/状态) · `reminders`(due_at/status/attempts) · `sandbox_approvals`(sha256 绑定) · `selfcheck_runs`(`report` 存 `{checks:[…]}` 非裸数组) · `telegram_state` · `todos`(status/due_date/ack_at/remind_count/escalated) · `tool_contract`(声明⊆实现基线) · `topic_watch` · `weekly_reviews`(week_start/week_end/content_md/stats_json) · `workflow_tools`(L2 注册表)

另三套正经 PG schema：`n8n/scripts/kb-schema.sql`（RAG：文档/分块/向量）、`ops-schema.sql`（告警与运维）、`platform-schema.sql`（平台状态机/outbox）。
LobeHub 的关键配置**只在数据库里**（`enableResponseApi` / `searchMode` / `useModelBuiltinSearch` / `system_agent` / `memory.enabled`）——恢复旧备份会静默打回未接线状态，所以有 `lobehub-config.mjs` 的 `status` / `apply` 两条命令。
